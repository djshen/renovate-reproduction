# mise lock-only update leaves stale URLs and checksums in `mise.lock`

Minimal reproduction for Renovate's `mise` manager.

## Current behavior

`mise.toml` has a fuzzy pin, `kubectl = "1.37"`, and `mise.lock` has it locked at 1.37.0.

Renovate opens **"Update dependency kubectl to v1.37.2"** (branch `renovate/kubectl-1.x-lockfile`), a lock-only update. The whole diff is:

```diff
 [[tools.kubectl]]
-version = "1.37.0"
+version = "1.37.2"
 backend = "aqua:kubernetes/kubernetes/kubectl"
-specifiers = ["1.37.0"]
+specifiers = ["1.37"]
```

The platform entries still point at the 1.37.0 release:

```toml
[tools.kubectl."platforms.linux-x64"]
checksum = "sha256:6129359f4e1f3848a5572ccb0b26cf28b8ca08cef38c95a765b2f64a2c961a2f"
url = "https://dl.k8s.io/v1.37.0/bin/linux/amd64/kubectl"
```

Installing from that lock succeeds, but installs the wrong binary under the new version's name:

```console
$ git checkout renovate/kubectl-1.x-lockfile
$ MISE_LOCKED=1 mise install kubectl          # exit 0
$ "$(mise where kubectl)/kubectl" version --client
Client Version: v1.37.0
```

## Expected behavior

The PR updates the `url` and `checksum` of every platform entry to 1.37.2, as a fresh `mise lock` would.

## Why it happens

`updateLockedDependency` rewrites `version =` and `specifiers =` only. The artifacts step then runs `mise lock kubectl` to refresh the platform entries. That runs, reports success and changes nothing:

```text
DEBUG: mise.updateLockedDependency: kubectl -> 1.37.2 [mise.lock]
DEBUG: Executing command  "command": "mise lock kubectl"
DEBUG: exec completed
       "stdout": "→ Targeting 2 platform(s) for .../mise.lock: linux-x64, macos-arm64\n→ Processing 1 tool(s): kubectl@1.37.2\n✓ Lockfile ready ..."
       "stderr": "mise lock ✓ 2 targets checked\n"
DEBUG: Updated 1 lock files  "updatedArtifacts": ["mise.lock"]
```

mise only re-resolves a platform entry when its URL visibly names another release, meaning a forge release tag or a version in the file name ([jdx/mise#15010](https://github.com/jdx/mise/pull/15010): "URLs with no release number are still reused as before"). kubectl's URL has the version in a middle path segment (`dl.k8s.io/v1.37.0/bin/...`) and the file is just `kubectl`, so mise treats the stale entry as current. The same check guards `mise install --locked` ([jdx/mise#13401](https://github.com/jdx/mise/pull/13401)), so the mismatch isn't caught there either.

## Suggested fix

When `updateLockedDependency` bumps a tool's `version`, also remove that tool's `[tools.<name>."platforms.*"]` tables, so `mise lock <tool>` must resolve them again. Otherwise return `unsupported` so the update goes through a full artifact refresh.

Workaround: a `postUpgradeTasks` command that deletes the tool's entry from `mise.lock` and runs `mise lock <tool>`.

## Files

- `mise.toml`: `kubectl = "1.37"`
- `mise.lock`: generated by `mise lock --platform linux-x64,macos-arm64` with `kubectl = "1.37.0"`, after which the pin was relaxed to `"1.37"`
- `renovate.json`: `config:recommended` only

## Environment

- Renovate 44.206.2, self-hosted CLI, `binarySource=global`, `allowedUnsafeExecutions: ["mise"]`
- mise 2026.10.25 (linux-x64)
- kubectl backend: `aqua:kubernetes/kubernetes/kubectl`
